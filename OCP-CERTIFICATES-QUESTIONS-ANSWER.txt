Question-2: Configure openshift cluster permission 

configure cluster permission so that,
1. Job can have cluster administration task
2. Remove the self-provisioner role to the system:authenticated:oauth virtual group
3. collins can create project* --> self provisoiner role collins cannot have cluster administration
task (note:- admin role youhave to add view role or we can add any role which is not cluster
admin role, anything apart from cluster admin role.)
4. Kubeadmin user should be deleted

## Answer:
oc adm policy add-cluster-role-to-user cluster-admin jobs
oc edit clusterrolebinding self-provisioners
--> bellow annotation set value as false
oc adm policy remove-cluster-role-from-group self-provisioner system:authenticated:oauth
oc adm policy add-cluster-role-to-user self-provisioner collins
oc adm policy add-role-to-user view collins
oc login -u jobs -p indionce
oc get nodes
oc delete secret kubeadmin -n kube-system

4. The user account aldrin is a member of the pilot group

Question-7: Scale an application automatically
Automatically scale the hydra deployment in the lerna project with the follow
Minimum number of pods: 1
Maximum number of pods: 9
Target average CPU utilization per pod: 60 percent
The pods require 25m CPU time to operate
The pods must not consume more than 180m CPU time

pre-requisite in lab:
 
 # oc new-project lerna
 # oc new-app  --name=hydra  --image=docker.io/openshift/hello-openshift
 # oc get deployment
 # oc get svc
 # oc expose svc hydra --hostname=hydra-lerna.apps-crc.testing 
    [Now the application is hosted on https://hydra-lerna.apps-crc.testing ]
	

Ans:
# oc project lerna
# oc set resources deployment hydra --requests=cpu=25m --limits=cpu=180m
# oc autoscale deployment hydra --min=1 --max=9 --cpu-percent=60
# oc get hpa

requirements: Complete and Continue

Traffic between the router and the service is unencrypted

/C=US/ST=NV/L=Hiko/O=CIA/OU=USAF/CN=classified.apps-crc.testing

https://classified.apps-crc.testing
